# 視線オーバーレイ for OBS

Webカメラ1台で視線を推定し、Tobii Ghost風の視線バブルをOBSの配信画面に重ねる。

```
4K Webcam → NVIDIA Broadcast(エフェクトなし)→ Camera (NVIDIA Broadcast) 1920x1080
                                               ├→ VMagicMirror
                                               └→ [Python] EyeTraxで視線推定 → One Euroフィルタで平滑化
                                                    → ゲームウィンドウ基準の座標 (u, v)
                                                    → WebSocket(127.0.0.1:8765 のみ)
                                                    → [OBSブラウザソース] 透過HTMLでソフトリングを描画
```

- 視線推定はCPUのみ(GPUは使わない)。1080pのまま推論して、プロセスのCPUは1コアの約95〜137%(全体の3〜4%)。`process_width = 960` にすると約55%(全体の1.7%)
- NVIDIA Broadcast はエフェクトなしで、CPU 1コアの約38%(全体の1.2%)、GPU SM使用率 約5%(nvidia-smi のプロセス単位の値)
- 顔の映像はOBSに一切入らない(OBSの仮想カメラや映像キャプチャデバイスは使わない)
- 計画と調査結果は `C:\Users\es2\.claude\plans\plan-async-blum.md` にある

## セットアップ

```powershell
cd C:\dev\eye_tracker
uv sync
```

Python 3.14(uv管理)を使う。依存関係の注意点は `pyproject.toml` の `[tool.uv]` を参照。

### カメラの共有(初回のみ)

Windowsの「マルチアプリカメラ」は使わない(オフに戻す)。確認したところ、共有できるのは Media Foundation のアプリ同士だけで、
VMagicMirror や OBS の映像キャプチャデバイス(DirectShow)とは共有できなかった。代わりに NVIDIA Broadcast でカメラを分配する。

1. NVIDIA Broadcast(2.2.1 で確認)の「カメラ」で、入力を「4K Webcam」にし、エフェクトはすべて外す
2. VMagicMirror のカメラを「Camera (NVIDIA Broadcast)」にする(4K Webcam を直接選ぶと、Broadcast が使用中なので映らない)
3. 視線ツールは `config.toml` の `[camera] name = "Camera (NVIDIA Broadcast)"` で同じ仮想カメラを読む(設定済み)
4. 次を実行して、映像が来ているか確認する

```powershell
uv run python tools/probe_camera.py
uv run python tools/probe_camera.py --hold 60   # 60秒開いたまま。VMagicMirrorが滑らかに動くか見る
```

NVIDIA Broadcast の仮想カメラは、出力と同じ 1920x1080 を要求しないと黒い画像が1秒に1枚しか来ない。
視線ツールは映像が来ない解像度だと自動で別の解像度を試す。起動順は NVIDIA Broadcast → VMagicMirror / 視線ツール。

## 起動

| 方法 | コマンド |
|---|---|
| OBSと連動(推奨) | OBSの「ツール」→「スクリプト」で `obs/gaze_overlay_launcher.lua` を追加する。以降はOBSの起動と終了に合わせて起動・終了する |
| 手動 | `scripts\start_gaze_overlay.bat` をダブルクリック |
| ターミナル | `uv run gaze-overlay`(`--debug-view` で視線カーソルをデスクトップに表示) |

起動中の確認や終了はタスクトレイのアイコンから行う。ログは `data\logs\gaze_overlay.log` に出力される。

### 初回のキャリブレーション

キャリブレーションのデータがないと、起動時に中央モニターが黒い全画面になり、9点キャリブレーションが始まる。点が出たら頭を動かさずに点を見つめる(約25秒。後半の4点は精度の検証用)。Escで中止できる。終わるとトレイに平均誤差が通知される。

まず `uv run gaze-overlay --debug-view` で、視線カーソル(ピンクの輪)が視線に追従するか確認するとよい。

## はじめての確認

バブルは「対象」があるときだけ表示される。既定の対象は**ゲームウィンドウ**で、`config.toml` の `[target] patterns` に
一致するゲーム(東方など)が前面になったときに決まる。ゲームを起動していないと「対象なし」になり、何も表示されない(配信に
変な位置のバブルを出さないため)。

1. OBSのブラウザソースのURLを `http://127.0.0.1:8765/overlay?debug=1` にすると、左上に状態(接続、状態、対象)が出る
   - `状態: no_target` … 対象のゲームがない。東方などを起動して前面にするか、下の方法でモニター全体に切り替える
   - `状態: tracking` で `表示: 1.00` … バブルが出ている
   - `接続: 未接続` … 視線ツールが起動していない
2. ゲームなしで試すときは、タスクトレイのアイコンを右クリック →「モニター全体を対象にする」。このときブラウザソースの
   幅と高さはモニターと同じ比率(例 1920x1080)にし、中央モニターの画面キャプチャに重ねる
3. パターンにないゲームは、ゲームを前面にして Ctrl+Alt+F8 で対象に固定する
4. 確認が終わったら `?debug=1` を外す

ドック(`http://127.0.0.1:8765/dock`)を追加しておくと、対象や状態、表示されない理由がいつでも見られる。

## OBSの設定

1. **ブラウザソース**を追加する
   - URL: `http://127.0.0.1:8765/overlay`(見た目はURLパラメータで変える。下記参照)
   - 幅・高さ: **重ねるゲームキャプチャの元のサイズと同じ**にする(ゲームキャプチャを右クリック →「変換」→「変換の編集」で確認)
   - 「カスタムフレームレートを使用」をオンにし、60にする
   - カスタムCSSは既定のまま(背景が透過になる)
   - 「表示されていないときにソースをシャットダウン」はオンでよい
2. ゲームキャプチャを右クリック →「変換」→「変換をコピー」。ブラウザソースを右クリック →「変換」→「変換を貼り付け」し、ゲームキャプチャのすぐ上に置く
3. 「ドック」→「カスタムブラウザドック」で `http://127.0.0.1:8765/dock` を追加する(操作ボタンと状態表示)

ドックに「縦横比が違います」と出たら、手順1の幅と高さを見直す。

### オーバーレイのURLパラメータ

例: `http://127.0.0.1:8765/overlay?size=0.15&color=ff4fa3&opacity=0.8`

| パラメータ | 既定値 | 内容 |
|---|---|---|
| `style` | `ring` | `ring`(ソフトリング) / `bubble`(塗りつぶし) / `glow`(放射グラデーション) |
| `size` | `0.12` | 直径(ソースの高さに対する比率) |
| `color` | `ffffff` | 色(`#` なしの16進数) |
| `opacity` | `0.7` | 不透明度 |
| `ring` | `0.16` | 輪の太さ(半径に対する比率) |
| `blur` | `0.10` | ぼかし(半径に対する比率) |
| `fill` | `0.06` | 輪の内側の不透明度 |
| `edge` | `1.0` | 領域外へのはみ出しの許容量(半径単位)。超えるとフェードアウト |
| `fadeOut` / `fadeIn` | `180` / `120` | フェードの時間(ms) |
| `follow` | `40` | 位置の補間の時定数(ms) |
| `trail` | `0` | `1` で軌跡を表示(`trailMs`、`trailCount` で調整) |
| `debug` | `0` | `1` で接続状態や座標を表示 |

## 操作

### ホットキー(`config.toml` の `[hotkeys.bindings]` で変更できる)

| キー | 機能 |
|---|---|
| Ctrl+Alt+F7 | 平滑化のプリセットを切り替える(安定 → バランス → 追従) |
| Ctrl+Alt+F8 | 前面のウィンドウを対象に固定する |
| Ctrl+Alt+F9 | バブルの表示を切り替える |
| Ctrl+Alt+F10 | 一時停止/再開 |
| Ctrl+Alt+F11 | クイック補正(対象の中央と四隅の5点、約7秒) |
| Ctrl+Alt+Shift+F11 | フルキャリブレーション(9点+検証4点) |
| Ctrl+Alt+F12 | 1点オフセット補正(対象の中央の点を約1.5秒見る) |

クイック補正と1点補正のマーカーは、クリックを透過しフォーカスを奪わない透明な窓に描かれるので、ゲームを操作したまま実行できる。実行中にもう一度ホットキーを押すと中止する。

### 頭を動かしたとき

Webカメラ方式は頭の位置が変わると精度が落ちる。ドックの「頭の位置」が黄色になったら(トレイのアイコンも黄色になる)、まず1点補正、ずれが大きければクイック補正、それでもだめならフルキャリブレーションを行う。

### 対象の決まり方

- 前面になったウィンドウのexe名が `config.toml` の `[target] patterns`(既定は東方などOBSのシーンにあるゲーム)に一致すると、そのウィンドウを対象にする
- その後ブラウザなどに切り替えても、ゲームのウィンドウが残っている間は対象のまま(ゲームの外を見ているときはバブルが消える)
- パターンにないゲームは、ゲームを前面にして Ctrl+Alt+F8 で固定する
- 画面キャプチャ(モニター全体)に重ねる場合は、ドックかトレイで「モニター全体」に切り替える

## 調整

`config.toml` を編集して再起動する。

- **画面の下を見るとバブルが消える**: `[tracker] blink_threshold_ratio` を下げる(例 0.5)。ドックの「目」に、目の開き具合(EAR)と基準値が表示される
- **ブレが大きい / 遅い**: 実行中に Ctrl+Alt+F7 でプリセットを切り替える。細かく調整する場合は `[smoothing.presets.balance]` を書く
- **ゲームによってバブルの位置がずれる**: OBSのキャプチャ範囲とウィンドウのクライアント領域が違う場合は、`[target.insets]` に exe名ごとの補正を書く

## トラブルシューティング

| 症状 | 確認すること |
|---|---|
| ドックが「未接続」 | Pythonが起動していない。ログ(`data\logs\gaze_overlay.log`)を確認する。OBS連動の場合はOBSの「スクリプトログ」も見る |
| 「カメラなし」 | `tools/probe_camera.py` でカメラ名と映像を確認する。名前が一覧にない場合は `config.toml` の `[camera] name` を直す |
| ドックに「映像が止まっています」 | NVIDIA Broadcast が起動していない(仮想カメラが静止画になっている)。Broadcast を起動する |
| VMagicMirror が映らない | VMagicMirror のカメラが「4K Webcam」になっている。「Camera (NVIDIA Broadcast)」にする |
| ホットキーに ✗ | 他のアプリが同じキーを使っている。`config.toml` で別のキーにする |
| 負荷を測りたい | `uv run python tools/bench.py`(プロセス自身のCPU時間で測る) |

## ファイル構成

```
src/gaze_overlay/   Python本体(app.py が入口)
  calibration/      キャリブレーション(進行、描画、保存、補正の計算)
web/                オーバーレイとドックのページ
obs/                OBS連動用のLuaスクリプト
scripts/            手動起動用のbat
tools/              カメラの確認と負荷の計測
models/             顔ランドマークのモデル(MediaPipe)
config.toml         設定
data/               キャリブレーション、ログ、実行中に変えた設定(自動生成)
```
